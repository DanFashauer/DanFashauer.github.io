01 / Why shared devices are different

Success is a session outcome, not an MDM status.

The visible endpoint problem

A device can be enrolled, compliant, and receiving policy while the actual user experience still fails because identity handoff, application state, connectivity, access policy, or operational ownership is wrong.

The systems problem

Multiple users, shifts, locations, applications, support teams, and security controls intersect on a single endpoint. That makes shared-device design an orchestration problem as much as a configuration problem.

03 / Decision questions

The questions I would ask before designing the solution.

IdentityWho is using the device, how is identity established, and what must happen to that identity at handoff or sign-out?
Device trustWhat endpoint state must be true before access is allowed, and what should happen when posture changes during use?
ContextDo role, location, shift, ownership, network, or environment change the expected access decision?
ApplicationsWhich apps retain user state, require certificates or SSO, depend on network paths, or behave differently in shared mode?
Failure handlingHow is a bad state detected, who owns remediation, how does the user recover, and what evidence reaches the support team?
LifecycleHow are updates, replacements, wipes, re-enrollment, lost devices, and retirement handled without breaking operations?
04 / State model

A useful way to reason about the session.

READYDevice is correctly enrolled/configured and available for a new user session.
ACTIVEUser identity, device posture, access policy, and application session are aligned for the operational task.
RECOVERY / HANDOFFSession closes cleanly, state is removed or reset as required, and the device returns to a known supportable condition.
05 / Validation

What I would test beyond enrollment.

User journey

Sign-in, application access, SSO behavior, policy application, handoff, sign-out, next-user readiness, and recovery from common failure states.

Operational journey

Support visibility, logging/evidence, escalation path, device replacement, patching, compliance recovery, incident recurrence, and clear ownership across teams.
