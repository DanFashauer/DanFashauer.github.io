01 / Automation & API Integration

Automated patch-ring orchestration for iOS and macOS

Built an end-to-end PowerShell workflow against the Workspace ONE UEM REST API to automate device cohort assignment across development, beta, and six production patch rings.

ProblemManual patch cohort assignment across multiple organizational groups did not scale cleanly.
What I ownedPowerShell orchestration, REST API interactions, scheduled execution, cohort logic, tagging model, Smart Group alignment, and validation.
Design decisionKeep native Workspace ONE policy targeting while implementing the custom cohort-selection logic in repeatable automation.
OutcomeReplaced manual ring assignment with a consistent workflow controlling when each managed device entered its patch cycle.

04 / Frontline & Rugged Mobility

Rugged-device lifecycle and controlled update strategy

Applied the same staged-management principle to Zebra Android devices using Workspace ONE and Zebra LifeGuard workflows before comparable update controls became available natively in the UEM platform.

ProblemFrontline devices need predictable update timing without disrupting operational availability across shared or shift-based workflows.
What I ownedUEM grouping and tagging approach, staged update logic, operational validation, and troubleshooting across the rugged-device lifecycle.
Design decisionUse controlled cohorts to balance update velocity with frontline operational risk.
OutcomeA repeatable staged-update model that could evolve as native platform capability improved.

How I work

Systems thinking before tool selection.

I am most effective when a problem crosses teams, platforms, and operational boundaries.

01

Frame the operating problem

Clarify user, business, security, support, and lifecycle outcomes before choosing the technical path.

02

Map dependencies

Identify identity, endpoint, network, application, vendor, governance, and support dependencies.

03

Make trade-offs explicit

Separate hard requirements from preferences and make risk, supportability, automation, and UX trade-offs visible.

04

Implement with specialists

Go deep where required, collaborate with domain experts, and keep the end-to-end outcome coherent.

05

Validate the real workflow

Test the intended operational outcome, not just whether a configuration technically succeeded.

06

Operationalize & document

Build repeatability through automation, supportable standards, documentation, ownership, and adoption.
